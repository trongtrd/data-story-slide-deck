# `deck-builder` — Slide Spec Compiler & Deck Build

> **Commands:** run every step as `python "${CLAUDE_PLUGIN_ROOT}/scripts/deckctl.py" <command>` (`python3` on macOS/Linux). `${CLAUDE_PLUGIN_ROOT}` is the plugin's install directory (three levels above this file if not filled in); `deckctl.py` switches to the plugin's own Python environment, and `doctor` explains anything missing (packages, a slide renderer: PowerPoint or LibreOffice).

- **Requires:** `context_brief.md` (`status: approved`) and `storyline.md` (`checkpoint_g2_status: approved`, `checkpoint_g3_status: approved`).
- **Reads:** both artifacts, `inputs/*`, the active language card (`LANG-EN` or `LANG-VI`).
- **Writes:** `artifacts/slide_spec.yaml` conforming to `${CLAUDE_PLUGIN_ROOT}/contracts/slide_spec.schema.yaml` (its golden example is `EX-001` slide 6, a `1x3` slopegraph), then `output/presentation.pptx` and `.html`, and `renders/slide_*.png`.

## Step 1: `deck_meta` and palette

- **Greyscale baseline (`PRIN-DSN-004`, `ANTI-DSN-001`):** `greyscale_baseline.context_series_hex` = `#9E9E9E` for `standalone`, `#8C8C8C` for `live` and `hybrid`; `context_line_width_pt: 1.5`; `zero_competing_dark_series_verified: true`. No rainbow defaults and no dark navy or black secondary lines competing with the focal series.
- **Colour kit (`D-030`, `PAT-DSN-002`):** from the G1 kit (`deck_meta.colour_kit`; values in `${CLAUDE_PLUGIN_ROOT}/contracts/colour_kits.yaml`) for the deck's `delivery_mode`, set `two_tier_accent.primary_focal_hex` = `focal`, `secondary_tint_hex` = `tier2` (a lighter tint of the same hue), `shaded_delta_fill_hex` = `shade`, `primary_focal_line_width_pt: 3.25`, `single_hue_hierarchy_verified: true`, `colorblind_safe_verified: true`. A second entity of equal importance takes the kit's `comparison` colour; never add a third accent. With `colour_kit: brand`, use the mapped brand colours; the validator holds them to the same floors.
- **Title slide (`D-075`):** set `deck_meta.title_slide` as follows:
  - `title`: the purpose or the answer in one line, ≤ 15 words or 25 syllables;
  - `audience_line`: who the deck is for, for example "Decision for the Operating Committee";
  - `date` and `presenter`: from the brief.
  The renderers draw it unnumbered before slide 1, and QA names its image `slide_00.png`. Turn it off only with `enabled: false` and a `disabled_reason`, for example when the slides go into a larger pack.
- **Design system (`PRIN-DSN-010`, `D-092`):** set `deck_meta.design_system: editorial` (rules in `${CLAUDE_PLUGIN_ROOT}/contracts/design_system.md`); write `classic` only when the brief records why. Fonts, sizes and text colours come from the system, never per slide.
- **Typography (`PRIN-DSN-003`, `PRIN-DSN-009`):** Editorial uses Aptos for labels and body and Aptos Display for titles; leave `deck_meta.typography` empty unless the brief names a brand face or Arial (Aptos missing on the presenting computers). A brand face must have normal width and weight, lining tabular figures and every glyph the deck language needs; a serif or display brand face goes in `title_font_family`, takeaway titles only. Align elements to a common top/left grid (`grid_alignment_verified: true`).

### Visual floors (`build`/`qa` check sizes, text effects and fill-plus-outline cards; the validator checks contrast and colour pairs)

- **Size (`PRIN-DSN-005`):** takeaway title / chart title and callouts / labels and axes / source footnote ≥ 20/10/9/8 pt `standalone`, 24/16/12/10 pt `live` and `hybrid`. If text cannot meet its floor, shorten it or split the slide; never shrink it. Sans-serif labels and body, 1.1–1.3 line spacing (upper end for Vietnamese), no text effects.
- **Distinguishable (`PRIN-DSN-006`):** colours in one panel stay apart under colour-vision deficiency and in greyscale (worst-case OKLab ΔE ≥ 0.12, lightness difference ≥ 0.05); fix with lightness first, then hue. No neon or pure hues; background very light or very dark and desaturated.
- **Contrast (`PRIN-DSN-007`)** against the slide or shaded-panel background: focal marks ≥ 3:1; context grey ≥ 2.4:1 standalone / 3.0:1 live and hybrid; tier-2 tint ≥ 1.6:1 / 2.0:1. Shaded deltas and panel fills are exempt.
- **Type levels and emphasis (`PRIN-DSN-008`):** ≤ 5 font sizes per slide, neighbours ≥ 1.5 pt apart (the renderer's type scale does this). Bold only for titles, panel titles, short headers, and one key phrase per annotation, callout or step paragraph (`color_tie_spans`): ≤ 5 words (EN) / ≤ 7 syllables (VI), ≤ 50% of the block. Card labels and `header_label` in sentence case, never ALL CAPS (classic `en` decks only: ≤ 4 words). Left-align every block over 10 words.
- **No decoration (`ANTI-DSN-002`):** no logos, icons or filler images (a logo the recorded brand template mandates goes only where the template puts it). A callout or panel card has a fill or an outline, never both.

## Step 2: Word jobs per slide (`PRIN-TTL-003`)

Every text element has one job; `EX-004` (*Kitchen Order Peaks*) shows all seven on one line chart with a threshold line and no repetition. Keep a top-left takeaway title over a neutral descriptive chart title (`PRIN-TTL-002`, `PRIN-DSN-001`, `upper_left_z_anchor: true`); every element supports the title (vertical logic).

1. **`takeaway_title`:** copy the approved Pass 2 title (`PAT-TTL-001`; `LANG-EN` ≤ 12 words, `LANG-VI` ≤ 20 syllables, Sentence case). Add a `color_tie_spans[]` entry (`substring`, `color_hex`, `linked_series_or_category`) on the phrase naming the focal cohort or metric, `color_hex` = `primary_focal_hex` (`G4.6`). **Omit `bold` on title spans**: the coloured phrase keeps the title weight; never write `bold: false` in a title (`D-035`). When the title names two entities with their own colours (focal and tier 2), tie both.
2. **`chart_title` / `panel_chart_title`:** neutral `<Metric (unit)> by <dimension>, <time period>`. One of the two on a single-panel slide (`G4.1`); on multi-panel slides `chart_title` names the shared metric and each `panel_chart_title` its panel. **Panel findings (`D-075`, `PAT-DSN-001` §3):** on `two_sided_paired_views` and `two_sided_comparison` give both panels a `panel_headline` (a claim, ≤ 8 words or 15 syllables, `color_tie_spans` as in the title, never the title again) and drop the card that would restate a panel; in `standalone` or `hybrid` decks add `panel_text` (≤ 2 lines) when the claim needs one sentence of support. The large panel of a `1_plus_4_grid` may carry one; small multiples do not. **Evidence columns (`D-075`, `PAT-DSN-001`):** on `evidence_columns` every panel carries a `column_heading` (the criterion, ≤ 3 words or 4 syllables) and a `panel_headline` of one sentence (≤ 14 words or 24 syllables); `word_jobs.recommendation_line` (≤ 25 words or 40 syllables) names the concrete decision and is not the title again; no `recommendation_callout`, `panel_text` or card annotation (a note must be anchored on a line or column chart).
3. **`axis_titles`:** explicit `x_axis_title` and `y_axis_title` with units.
4. **`direct_labels_mode`:** `series_endpoints`, `both_endpoints`, `bar_values` or `min_max_endpoints`, so `detached_legend` stays `false`.
5. **`annotations[]` (`PAT-VIS-012`):** callouts anchored to a peak, trough, crossover or threshold (`anchor_data_point`: a category or series of the target panel; `anchor_end_data_point` for a period; at most two per panel; each says what happened there), with `color_tie_spans` on highlighted numbers. Supporting figures from the storyline go here or in direct labels.
6. **`recommendation_callout` and annotations (`D-059`):** side cards do one job: why the chart matters, the implication, or an action; a card that only restates the title or subtitle is dropped and the space stays empty. **Never repeat the takeaway title** (`distinct_from_takeaway_title: true`, `no_triple_headline_repetition_verified: true`; `ANTI-TTL-002`: no stacked title, subtitle and callout saying the same thing — but no bare over-minimalism either). With no ask (shared understanding), `kind: implication` stating what the finding means. Never a reading note or method caveat (`D-035`, `D-058`).
7. **`source_footnote`** (and optional **`reading_note`**; the renderers add the slide number at the right, `D-075`; in `standalone` or `hybrid` decks set `deck_meta.footer_label` to a short deck name from the brief, ≤ 5 words): source document or table, `n`, date range, bottom left. One short sentence stating the chart's unit, base or coverage goes in `reading_note` (how to read the chart goes in speaker notes, `D-059`), no `Note:` prefix; the renderer sets it above the source in the same quiet style. Long detail goes to speaker notes. **No caveat cards (`D-058`):** annotations and callouts carry insights and implications, never sample-size or caution caveats; an essential caveat is the `reading_note`, and one that contradicts the title changes the title (`G4.8`). Never tell the audience how to read ("cần đọc", "should be read").
8. **Speaker notes** (`progressive_reveal.reveal_steps[].speaker_notes`): what the presenter says, in the deck language, numbers formatted as on the slide; it may simplify a claim, never strengthen it (`D-049`). No file or cell references, raw field names, interval dumps, or instructions to the agent; traceability lives in `source_cell_ref` (`D-035`).

**Delivery mode (`PRIN-PRS-001`, `PAT-PRS-001`):** `standalone` and `hybrid` decks carry self-sufficient annotations (`standalone_self_sufficient_verified: true`); `live` decks keep text lean with speaker notes, and complex slides get `reveal_steps[]` (step 1 grey context, step 2 focal series with annotations and callouts).

## Step 3: Chart panels (`visual_spec.panels[]`)

1. **Native and decluttered (`ANTI-VIS-002`, `PRIN-DSN-002`):** `render_mode: native_editable_chart`, never a picture of a chart. `declutter_rules` take the fixed values the contract requires (borders, minor gridlines, tick marks, legends and attached tables off; trailing zeros stripped; forecasts dashed).
2. **Family and layout (`PRIN-VIS-002`, `PAT-DSN-001`, `PAT-VIS-002`):** the G3 workhorse `chart_family` and `layout_type`; small multiples (`1x3`, `2x2`) or `1_plus_4_grid` (`hero_total_left` + four `small_multiple_cell`) with clean `grid_position`. Dot plots (`PAT-VIS-005`): `orientation: horizontal` for long names; `dot_style: connected` = two series (start, end), `connector: line | arrow`, `category_order`, and speaker notes saying what the line or arrow joins. Bars and dot plots (`PAT-VIS-004`): `category_scale: nominal` sorts by value, `ordinal` (time, age bands, Likert) keeps the given order. A one-series `horizontal_bar_chart` takes `side_column` (`title`, plus a signed, traced `data_points` entry per category) when the title is about each bar's gap to a reference such as plan or last year (`D-095`). Stacks (`PAT-VIS-004`): `orientation`, `stack_mode: count | percent | diverging`, focal segment first; diverging series carry `diverging_side`, listed negative → positive (`side_totals: brackets` adds each side's total under horizontal diverging bars when the title compares one side across bars, `D-088`), with `colour_scale: diverging` and each side stepping to its kit tint for the delivery mode (`tier2`, `comparison_tier2`; `D-060`). A scatter plot (`D-065`) is `scatter_plot`: numeric `x_axis.min`/`max`/`number_format`; every point adds `x_value` + `x_source_cell_ref`; `reference_lines` (≤ one per axis; `axis: diagonal` draws the y = x equal-change line when both axes share range and format, `PAT-VIS-010`, `D-088`), `section_labels` (≤ 4 words), `label_points: focal` (or `all` up to 10 points), `trend_line: linear` only with `trend_reason`; pick axis ranges whose tick step the format can show. A strip plot (`PAT-VIS-013`, `D-086`) is `strip_plot`: rows (the measures) in `x_axis.categories`, one shared `y_axis` (`min`, `max`, `number_format`, `title`); a context series whose points carry `category` (the row), `item` (who the dot is), `value` and `source_cell_ref`, and one focal series with exactly one point per row; optional `median_line: true`; `highlight_band` (`top_fifth`, `bottom_fifth`, `top_quarter`, `bottom_quarter`) with `highlight_band_label` (≤ 3 words, the title's words) only when the title names that part; speaker notes say what one dot is. Time categories (`ANTI-VIS-005`): years with unequal gaps need `time_spacing_reason` (or show only evenly spaced periods); month or day ticks need the year on a tick or in the panel or chart title. A waterfall (`PAT-VIS-011`, `D-067`) is `waterfall_chart`: one series; every point has `step_type` (`start`, `delta`, `total`), a signed `value` and `source_cell_ref` (`aggregation: diff` for a difference of two cells); `waterfall_mode: changes_only` (changes grow from zero, derived net bar, `net_label`) when the largest change is under 10 % of the pillar, else `full` with a zero-based axis; `y_axis.min`/`max` include zero; no subtotals; `connector_lines` on. A look-up table (`PAT-VIS-006`) is `data_table` with `table_spec`: key column first, number cells with `formatted_label` and `source_cell_ref`, one focal row, column or ≤ 3 cells. A heatmap table (`D-068`) adds `table_spec.heatmap`: `scale` (`per_column` for mixed units, `shared` with one `unit` and one `dark_end` on every shaded column, which draws a key), `steps` (5; 0 = continuous), and `columns` of `col_id` + `dark_end` (the end the title names) with `scale_type: diverging` + `midpoint` only for a signed column; speaker notes say what the colour shows. A diagram (`D-069`) is `layout_type: diagram` with `diagram_spec`: `diagram_type`, `g3_tradeoff_record`, `diagram_title`, `alt_text` and the type block; never coordinates. `process_flow`: `style: boxes` (glued arrows) or `numbered` (no arrows), `steps[]` with `step_id`, a short `label`, an optional `sublabel`, one or two `focal: true`, and a `source_cell_ref` on every step whose text has a figure or date; `timeline`: `form: milestones | bars`, quoted `start` and `end` dates, `unit` (month by default), optional `today`, `items[]` with `item_id`, `label`, a `date` or (bars) a `start` and `end`, one or two `focal: true`, and a `source_cell_ref` on every item; `matrix_2x2`: `variant: positioning | scenario`, `x_axis` and `y_axis` (`title`, one-word `low_label` and `high_label`), then either `items[]` (`x`, `y` in 0–1 and never within 0.06 of 0.5, `placement_basis: data | judgement`, one or two `focal`, a `source_cell_ref` for data placements) or exactly four `cells[]` (`cell_id` tl, tr, bl, br; a real `name`; exactly one `focal`); `decision_flow` (`D-071`): `nodes[]` in main-path order (`node_id`, `kind: start | step | decision | end`, `label`, optional `sublabel`, one or two `focal`, `source_cell_ref` on figures) and `edges[]` (`from`, `to`, an `answer` of ≤ 14 characters on every decision exit, the main-path exit listed first; a decision's second exit drops below, its third rises above, and a branch node may only rejoin a later main-path node); `swimlane` (`D-071`): `lanes[]` (`lane_id`, `name`), `steps[]` in process order (`step_id`, `lane_id`, `label`, optional `sublabel`, `focal`) and an optional `focal_handoff` (`from`, `to` of two consecutive steps in different lanes, a `label` of ≤ 14 characters with `source_cell_ref` on a figure); one or two focal elements in all; `tree` (`D-071`): `direction: right | down`, `additive: true` when children sum to their parent, `nodes[]` (`node_id`, `parent` on every node but the root, `label`, `value` + quoted `value_label` + `source_cell_ref` on figures, `focal` on the root or one leaf, never both); reveal steps may list `visible_item_ids`. Evidence columns (`D-075`): `layout_type: evidence_columns` with 2-3 panels of `panel_role: evidence_column`, each a bar, column, line or dot-plot chart with ≤ 6 categories and ≤ 2 series; an entity keeps one colour in every column and the same options keep one order; in a `live` deck add one reveal step per column (`visible_panel_ids` grows by one). Executive summary (`D-075`): the first main slide when `storyline.md` has `opening_summary.enabled: true`; `arc_stage: summary`, `layout_type: executive_summary`, `word_jobs.summary_points[]` (`lead` ≤ 15 words or 25 syllables, optional one-sentence `detail`, `evidence_slides` from the section's slides, optional `color_tie_spans`); no chart, annotations, steps or callout. Key slides (`D-063`): `section_divider` takes `layout_spec.section_number` and `word_jobs.section_question` (one line) and nothing else; other key slides set `layout_spec.emphasis: key` with `emphasis_reason` (the closing decision slide needs neither). Big-number tiles (`D-064`): `step_style: big_number`; each step's `title` is the shown number, `description` a short caption, plus `source_cell_ref` and at most one `focal: true`; `emphasis: spotlight` once per deck. A content image beside the main card is `word_jobs.side_image` (`path` in `inputs/`, `alt_text`, `referenced_in`), never decoration.
3. **Scale (`PAT-DSN-003`, `PRIN-VIS-004`):** `shared_y_axis: true` → identical `y_axis.min`, `max` and `number_format` on every panel; `shared_y_axis: false` → `non_uniform_scale_justification`, `non_uniform_axis_label_mode: min_max_only`, `require_direct_endpoint_labels: true`. Bar families: `y_axis.min: 0` (non-negative data), `y_axis.max: 0` (non-positive), or zero inside the range (mixed). `line_chart`, `slopegraph`, `dot_plot` axes above zero keep the data within 80% of the span.
4. **Colour (`PRIN-VIS-005`, `PAT-DSN-004`, `PAT-DSN-002`):** apply each panel's G3 `colour_scale` (`diverging` needs `colour_midpoint`; `sequential` is one hue, lightness in category order) and the G3 colour map: never recolour an entity or move the accent to a new entity while the old one is still shown; a second focal entity takes the second accent family. Use `shaded_deltas[]` between crossing lines and `is_focal_panel_shaded: true` (`#F3F4F6`) for a priority panel. `EX-003` (*Menu Sales*): `point_visual_role_override` gives tier 1 to the two steepest drops, tier 2 to two mild drops, grey to six growing drinks.
5. **Series:** context series `visual_role: context_greyscale`; the series proving the title `focal_primary_tier1` (sparingly), optionally `focal_secondary_tier2`. `is_forecast: true` on projected points (dashed). `source_cell_ref` on every data point (`PRIN-AI-003`, `G4.9`).
6. **Model estimates (`PRIN-VIS-006`):** `ci_low`/`ci_high` with their own source refs, the unit named on the slide, non-significant estimates in the context tier, and comparisons only within one model, scale and reference group (or `comparison_valid_reason`).
7. **Labels (`PAT-DSN-005`):** keep category labels short; when the build reports a collision, shorten them or switch to `horizontal_bar_chart`.

## Step 4: Claim vs evidence (`G4.8`)

Compare `claimed_construct_in_title` with `plotted_metric_on_chart` and set `claim_evidence_contract.strict_claim_match_verified` only when they match. If the title claims an unmeasured cause ("widening the new-nurse support gap" over a "Mean competency score" axis), rewrite it to claim the measured metric ("Competency scores fell for new-graduate nurses after rotation began") and put the explanation in `annotations[]` or `recommendation_callout`.

## Step 5: Validate and build

1. Save the spec. Rules the validator enforces:
   - **Every number traces to `inputs/`:** paths relative to `inputs/` (`tables/t2.csv!R12C4`, not `inputs/tables/…`); `source_cell_ref` is `file.csv!R2C4` (1-based; header = row 1), `file.csv!R2C4:R5C4` or `file.csv!R2C4,R7C4` plus `aggregation` (`sum|mean|min|max|diff`), or `report.md!<exact heading>` (or `report.txt!<exact evidence line>`) when the signed number is quoted in that unique section or line. For model estimates add `ci_low` / `ci_high` with `ci_low_source_cell_ref` / `ci_high_source_cell_ref` (the renderer draws native whiskers or error bars), `significant` where known, `unit_kind` when a panel holds model output (one kind per panel), `direct_label_placement: bar_end` on `dot_whisker_chart` series so every estimate shows its value (`D-043`), and the unit in the chart title or `reading_note` when the value axis is hidden; fill `claim_evidence_contract.population`, `estimand` and, when estimates from different models or references share a slide, `comparison_valid_reason` (`D-040`). `source_unit_factor` converts units (e.g. `0.001` for *450 triệu → 0,45 tỷ*). `value` equals the source and `formatted_label` agrees with `value`. A number that cannot be traced is removed — never invent a reference.
   - **No internal vocabulary in audience text:** no card IDs (`PAT-…`, `EX-…`), gate IDs (`G4.7`), cell references or design jargon (*Focal*, *Tier 1 orange*) in titles, labels, annotations, callouts or footnotes.
   - **One weight per title; quiet notes; clean speaker notes (`D-035`):** a title span with `bold: false` needs `mixed_weight_reason`; `reading_note` fits one line; speaker notes with file or cell references or unformatted numbers fail.
   - **First render (`P7-A4`):** leave `rendered_png_qa.zero_text_overlap_or_clipping` and `compound_word_linebreak_safe` (`LANG-VI`: two-syllable *từ ghép* never split across lines) `false` until someone has looked at the renders; with `g4_review_audit.status: pending` the build accepts that. The reviewer sets them after inspection; a completed agent review with unset flags fails validation.
   - **Colour-tie text stays legible:** every `color_tie_spans` hex reaches ≥ 3:1 on its background (use a darker shade of a pale tier-2 tint for text).
   - **Copy lives in the spec, never in renderers:** statement slides list cards in `word_jobs.implementation_steps`; extra peak labels use `label_categories`; short series names use `direct_label_name`; stacked totals use `stack_total_labels`.
   - Number formats follow the language card (`LANG-EN`: `$#,##0M`, `0.0`, `0%`; `LANG-VI`: consistent Vietnamese numbers and units).
2. Validate:
   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/scripts/deckctl.py" validate --workspace <user-deck-workspace>
   ```
3. Build (requires approved, valid G1–G3 artifacts; rechecks source data; G4 may be pending):
   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/scripts/deckctl.py" build --workspace <user-deck-workspace>            # add --live-reveal for live decks
   ```
   It writes `output/presentation.pptx` and `.html`, checks the `.pptx` text against the size floors, text effects and fill-plus-outline cards, then renders `renders/slide_*.png` **from the compiled `.pptx`** (PowerPoint when installed, else LibreOffice; `D-020`, `D-044`) with a `render_manifest.json` of source hashes. A typography failure means shorten text or split a slide, never shrink. With neither renderer, `build` still writes the deck and puts labelled Pillow previews in `renders/` (`render_source: pillow_preview`): tell the user plainly these are not images of the deck, ask them to open `output/presentation.pptx` and check every slide themself, and do not ask them to install anything unless they want automatic QA images. Pillow previews are never G4 evidence for `.pptx` decks.
   **Hand edits (`D-062`):** a repair changes only the slides the user or reviewer named; every other slide's spec stays as it is. When `build` warns that a `.pptx` changed after the last build, it has kept the user's copy as `*.edited-<time>.pptx`: ask which edits to keep and carry them into the spec before G4.
4. Hand off immediately to `deck-reviewer` for G4.
