# Context Brief Artifact Schema (`30_design/contracts/context_brief.schema.md`)

> **Artifact Path in User Workspace:** `<user-deck-workspace>/artifacts/context_brief.md`
> **Produced By:** `deck-context-griller`
> **Gate:** `Checkpoint Gate G1` (Mandatory Human Stop)
> **Enforces Checklist:** [`CHK-REV-001`](../../20_knowledge/checklists/CHK-REV-001_context-and-storyline-gate-checklist.md) Part A (`G1.1` through `G1.6`)
> **Related Cards:** `PRIN-CTX-001..005`, `PAT-CTX-001..002`, `ANTI-CTX-001`, `PRIN-PRS-001`, `PRIN-AI-001..003`, `ANTI-AI-001..002`

---

## 1. Purpose

`context_brief.md` is the first stateful artifact in the **Data Story Slide Deck** pipeline (`D-001`, `D-010`). It locks the strategic foundation of the deck—who is in the room, what single decision is requested, what is at stake, the single-sentence `Big Idea`, and the delivery/rendering configuration—before any slide storyboarding or chart generation begins.

---

## 2. Deterministic Traceability to `CHK-REV-001` (Part A)

Every field in `context_brief.md` maps directly to a mandatory gate check in `CHK-REV-001`:

| `CHK-REV-001` Check ID | Rule Enforced | Schema Field(s) Enforcing the Check |
|---|---|---|
| **`G1.1` Explanatory Mode Confirmed** (`PRIN-CTX-001`) | Deck is framed around `Audience` decision needs (`Explanatory Communication`), not replaying `Exploratory Analysis`. | `communication_mode: explanatory` + Section 1 (`Exploratory-to-Explanatory Boundary`) |
| **`G1.2` Stakeholder Decomposition** (`PRIN-CTX-002`) | `Audience` decomposes the primary decision-maker/champion, allies, and skeptics with concrete priorities and biases. | `audience_map.primary_decision_maker`, `audience_map.allies`, `audience_map.skeptics` (or `audience_map.resistance_assessment: none_identified` with a reason — `D-035`) + Section 2 |
| **`G1.3` Unbundled `Primary Action`** (`PRIN-CTX-003`, `ANTI-CTX-001`) | Exactly one realistic decision or approval is requested for the immediate meeting; fallback concessions are separated. With `action_contract.objective: shared_understanding` (research, assessment and briefing audiences — `D-040`) no ask is invented: the deck closes on what the findings mean. | `action_contract.objective`, `action_contract.primary_action`, `action_contract.bundled_actions_check`, `action_contract.fallback_concession` + Section 3 |
| **Research inputs** (`PRIN-AI-003`, `D-040`) | When the inputs are statistical or research results, the brief records the study design and the population the estimates describe; observational designs never carry causal wording, and the storyline keeps an evidence ledger. | `study_design`, `analysed_population`, `audience_assesses_method` (`D-046`) |
| **`G1.4` Dual-Sided Concrete `Stakes`** (`PRIN-CTX-004`, `ANTI-CTX-001`) | Both concrete benefits of acting and concrete risks of inaction are specified without hollow buzzwords. | `strategic_stakes.benefits_of_action`, `strategic_stakes.risks_of_inaction` + Section 4 |
| **`G1.5` Single-Sentence `Big Idea`** (`PRIN-CTX-005`, `PAT-CTX-002`) | `Big Idea` is a single complete grammatical sentence containing active point of view and `Stakes` (using directional phrasing if exact figures invite premature methodology nitpicking). | `big_idea.sentence`, `big_idea.sentence_count` (`== 1`), `big_idea.point_of_view`, `big_idea.stakes_clause`, `big_idea.phrasing_mode` + Section 5 |
| **`G1.6` Delivery & Language Metadata** (`PRIN-PRS-001`, `D-008`, `D-011`) | `Delivery Mode`, target format, target language (`LANG-*`), and brand palette constraints are explicitly recorded. | `delivery_metadata.delivery_mode`, `delivery_metadata.target_format`, `delivery_metadata.deck_language`, `brand_profile` + Section 6 |

## 3. Canonical File Template & Schema (`context_brief.md`)

Every `context_brief.md` generated by `deck-context-griller` must strictly follow the YAML frontmatter + Markdown structure below:

```markdown
---
artifact_type: context_brief
schema_version: "1.0"
checkpoint_gate: G1
status: draft                  # draft | approved
# approvals:                    # written by `validate_spec.py --stamp-approval --gate G1` only after the user approves (D-021)
#   G1: { approved_by: "<user>", approved_at: "<UTC ISO-8601>", content_sha256: "<hash of frontmatter minus approvals + body>" }
created_at: "YYYY-MM-DDTHH:MM:SSZ"
updated_at: "YYYY-MM-DDTHH:MM:SSZ"

# G1.1 — Explanatory Mode Confirmation (PRIN-CTX-001)
communication_mode: explanatory # MUST be 'explanatory' (never 'exploratory')
source_inputs:
  - path: "inputs/source_report.md"  # must exist in the workspace (validator, D-040)
    type: document             # document | dataset
    verified: true
# Research inputs (D-040) — set when the deck reports statistical or research results:
# study_design: observational_cross_section   # experimental | quasi_experimental | observational_cross_section | observational_panel | descriptive
# analysed_population: "<Who the estimates describe, e.g., Australian adults who rent or hold a mortgage, Jan 2024>"
# audience_assesses_method: true   # D-046: the audience judges the method (assessor, examiner, reviewer); inferred from the decision-maker's role when absent
# quote_speaker_names: allowed   # D-108: quote slides may name speakers; without it a speaker is described by role and place

# G1.2 — Stakeholder-Specific Audience Map (PRIN-CTX-002)
audience_map:
  room_summary: "<Specific governance body or decision forum, e.g., Executive Leadership Team>"
  meeting_date: "<D-075: meeting or issue date as the audience will read it, for the title slide>"
  presenter: "<D-075: presenter or team named on the title slide>"
  primary_decision_maker:
    name_or_role: "<Specific name/title, e.g., Grace Adeyemi (CEO) and the Executive Leadership Team>"
    decision_authority: "<Exact authority in this meeting>"
    core_priority: "<What they care about most>"
  allies_and_champions:
    - name_or_role: "<Name/Role>"
      priority: "<What motivates their support>"
      evidence_needed: "<What proof arms them to advocate in the room>"
  skeptics_and_veto_holders:      # only real, expected resistance; never invented (D-035)
    - name_or_role: "<Name/Role, e.g., Tomás Reyes (CFO)>"
      core_bias_or_fear: "<Specific objection or risk sensitivity, e.g., Expects the current policy to keep agency spend down>"
      required_reframe_or_proof: "<How the deck will answer this objection>"
  # resistance_assessment: none_identified   # use instead of skeptics when the user identifies no resistance
  # resistance_reason: "<One line, e.g., Briefing for shared understanding; no decision is contested>"

# G1.3 — Unbundled Single Primary Action (PRIN-CTX-003, ANTI-CTX-001)
action_contract:
  objective: decision                # decision | shared_understanding (D-040). Recommend shared_understanding for research, academic and assessment audiences
  primary_action: "<Exactly ONE concrete decision, approval, or resource commitment requested today>"  # optional with shared_understanding; never invent an ask
  is_single_unbundled_action: true   # MUST be true; no 'align AND approve AND launch' chains
  fallback_concession: "<Optional lower-barrier fallback if full approval stalls, e.g., 6-month pilot in 2 departments>"

# G1.4 — Dual-Sided Strategic Stakes (PRIN-CTX-004, ANTI-CTX-001)
strategic_stakes:
  benefits_of_action:
    - "<Concrete strategic/financial/human gain if Primary Action is taken>"
  risks_of_inaction:
    - "<Concrete strategic/financial/human loss if status quo continues>"
  zero_generic_buzzwords_verified: true

# G1.5 — Single-Sentence Big Idea (PRIN-CTX-005, PAT-CTX-002)
big_idea:
  sentence: "<Single complete grammatical sentence stating point of view + Stakes>"
  sentence_count: 1                  # MUST equal 1
  point_of_view: "<Extracted active claim/recommendation>"
  stakes_clause: "<Extracted consequence for the Audience>"
  phrasing_mode: directional         # directional | quantified (use 'directional' per PAT-CTX-002 when exact modeled numbers invite premature methodology nitpicking)
  phrasing_rationale: "<Why directional or quantified phrasing was chosen for this room>"

# G1.6 — Delivery Mode, Target Format, Language & Brand Profile (PRIN-PRS-001, D-008, D-011)
delivery_metadata:
  delivery_mode: live                # live | standalone | hybrid
  speaker_present: true              # true for live/hybrid; false for standalone
  target_format: pptx                # pptx | html
  deck_language: en                  # en | vi | zh | es | pt | ja | ko
  language_rule_card: LANG-EN        # LANG-EN | LANG-VI

brand_profile:
  organization_name: "<Client or Org Name>"
  typography:
    heading_font: "Arial"           # takeaway titles only -> slide_spec deck_meta.typography.title_font_family (PRIN-DSN-009, D-029)
    body_font: "Arial"              # labels and body -> deck_meta.typography.font_family; plain sans-serif with full glyph coverage

    text_primary_hex: "#1F2937"
    greyscale_baseline_hex: "#9E9E9E" # Context grey (PRIN-DSN-004); #8C8C8C for live/hybrid decks (PRIN-DSN-007)
```

## 4. Validation Rules & Hard Constraints

1. **Block on Monolithic Audience Labels (`G1.2`):** If `audience_map.primary_decision_maker.name_or_role` contains only a generic noun (`"Executives"`, `"Leadership"`, `"Clients"`, `"The Board"`) without mapped priorities, `G1` validation **fails**. It also fails when there is neither a skeptic/veto-holder profile nor `resistance_assessment: none_identified` with a `resistance_reason` (`D-035`); never invent a skeptic to pass.
2. **Block on Compound Action Chains (`G1.3`):** If `action_contract.primary_action` joins multiple sequential steps across different timelines (e.g., *"Align on findings, approve a task force, and roll out the new policy in Q3"*), `G1` validation **fails** (`ANTI-CTX-001`).
3. **Block on Multi-Sentence or Stake-Less `Big Idea` (`G1.5`):** `big_idea.sentence` must contain exactly one terminal sentence boundary (`.` / `!`) and must include both an active recommendation verb and a consequence clause (`Stakes`).
4. **Block on Red-Green Palettes (`G1.6`):** `brand_profile.palette.focal_accent_primary_hex` and `focal_accent_secondary_hex` must be shades/tints of a single accessible hue (or high-contrast accessible pair) with `colorblind_safe_verified: true`.
